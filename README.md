# Intent Workflow Runtime

Intent Workflow Runtime превращает пользовательскую задачу в проверяемый план,
выполняет его в изолированном Docker-контейнере и принимает результат только
после независимых проверок. Модель может предлагать намерение и workflow, но не
может самостоятельно расширять разрешения, пропускать обязательные проверки
или объявлять свою работу успешной без подтверждений.

## Возможности

- Поддержка OpenAI, Anthropic, OpenRouter и совместимых API.
- Полная JSON Schema для намерений и workflow.
- Изолированное выполнение без root-доступа и без сети по умолчанию.
- Разрешение сети только для явно указанных доменов.
- Независимые механические проверки результатов.
- Автоматическое исправление неудачного шага с ограниченным числом попыток.
- Транзакционная публикация результатов: неудачная попытка не изменяет рабочую папку.
- Защищённое хранение API-ключа в системном хранилище учётных данных.
- Audit trail, восстановление прерванных запусков и диагностические endpoints.

## Требования

- Windows 10/11 или современный Linux.
- Python 3.11 или 3.12.
- Docker Desktop на Windows либо Docker Engine на Linux.
- Не менее 1 ГБ свободного места на выбранном диске.
- API-ключ поддерживаемого LLM-провайдера.

Для Windows с небольшим системным диском распакуйте релиз на другой диск,
например `D:\Apps\iw-runtime-v3`. Виртуальное окружение и файлы runtime будут
созданы в этой же папке.

## Установка на Windows

1. Скачайте подписанный архив релиза и распакуйте его в постоянную папку.
2. Запустите Docker Desktop.
3. Откройте PowerShell в папке runtime и выполните:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\install.ps1
```

Установщик проверит Python и Docker, создаст локальное `.venv` и установит
зафиксированные по SHA-256 зависимости.

## Установка на Linux

```bash
chmod +x install.sh
./install.sh
```

## Настройка модели

Откройте `.env` и укажите провайдера, endpoint и модель. Секретный API-ключ в
этот файл добавлять не нужно.

Пример для OpenRouter:

```dotenv
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=openai/gpt-4o-mini
LLM_STRUCTURED_OUTPUT_MODE=json_schema
IW_SECRET_SOURCE=keyring
```

Сохраните API-ключ в системном хранилище Windows:

```powershell
.\.venv\Scripts\python.exe -m runtime.secret_cli set llm_api_key
```

На Linux используйте `.venv/bin/python` вместо `.venv\Scripts\python.exe`.

## Проверка установки

```powershell
.\.venv\Scripts\python.exe -m runtime.cli doctor
```

Готовая система вернёт статус `ready` и успешные проверки Python, Docker и LLM.
Команда не отправляет запрос модели и не расходует токены.

## Первый запуск

В комплект входит безопасная демонстрационная задача, создающая простой
Python-файл внутри временной рабочей папки:

```powershell
.\.venv\Scripts\python.exe examples\example_run.py
```

Во время первого запуска Docker может скачать закреплённый sandbox-образ.

## Мониторинг

```powershell
.\.venv\Scripts\python.exe -m runtime.observability_server --port 9090
```

После запуска доступны:

- `http://127.0.0.1:9090/health/live`
- `http://127.0.0.1:9090/health/ready`
- `http://127.0.0.1:9090/metrics`

## Обновление

1. Остановите новые задачи.
2. Скачайте и проверьте новый подписанный релиз.
3. Распакуйте его в новую папку, не поверх работающей версии.
4. Запустите установщик и команду `doctor`.
5. Переключитесь на новую папку только после успешной проверки.

Предыдущую папку сохраняйте до подтверждения стабильной работы — это позволяет
быстро выполнить rollback.

## Удаление

Удалите папку runtime и при необходимости удалите credential:

```powershell
.\.venv\Scripts\python.exe -m runtime.secret_cli delete llm_api_key
```

Docker-образы можно удалить отдельно через Docker Desktop. Audit-файлы и
рабочие результаты перед удалением сохраните, если они нужны для отчётности.

## Ограничения безопасности

Docker-контейнер является сильной практической границей для обычных задач, но
не заменяет отдельную виртуальную машину для обработки заведомо враждебного
кода или особо чувствительных данных. Ручные критерии всё равно требуют решения
человека. Используйте только подписанные релизы и не запускайте runtime с
правами администратора без необходимости.

## Поддержка

Перед обращением приложите результат `runtime.cli doctor`, версию релиза и
описание задачи. Никогда не отправляйте API-ключ, содержимое системного keyring
или неочищенные audit-логи.
